# OCT training loop: operational notes

For agents running the first recursive training run: Qwen3.8 27B edits its constitution, is trained on it with the OCT recipe (LoRA), and edits again, for 5 rounds from the broad draft. The design decisions are in [reports/methods/oct_recipe.md](../../../reports/methods/oct_recipe.md); account and RunPod workflow as in the [stage 08 notes](../08_selfhost_9b/NOTES.md). Nothing here has run on a GPU yet.

## Configs

- `configs/oct-loop/qwen38-27b-broad.json`: the run. OCT recipe at 100% (`configs/oct/recipe-100.json`), 5 rounds, adapters to the public repo `JinzhouWu/value-drift-oct-qwen3.8-27b-broad`.
- `configs/oct-loop/qwen38-27b-broad-pilot20.json`: a smaller engineering pilot, one round at 20% (`recipe-20.json`), adapters to a private repo. Not used: the user chose a full-scale first round instead.
- **Pilot = round 1 of the run.** Launch the run's own config with `--stop-after-round 1`: the run pauses (status `PAUSED`) after round 1, and rerunning with `--resume` (without the flag) continues to round 5 with the same protocol, so round 1 is not paid for twice.
- `run_experiment.py` expands the recipe into the run's `config.json` and snapshots the protocol inputs, including the elicitation harness's review code.

## What each round does

1. **Review** (`recursive_oct/review_v3.py`): serves the current checkpoint with `vllm serve` (stage 07's flags) and runs one "reflect" review with the elicitation harness (prompts v3, thinking on). An unchanged submission still trains (`continue_when_unchanged`); only a failed review ends the run. An interrupted review resumes by replaying its saved calls.
2. **Preferences, DPO, introspection, SFT** as in the recipe. Generation uses the in-process vLLM worker (`recursive_oct/vllm_worker.py`) with 256 sequences.
3. **LoRA** (`recursive_oct/train.py`, `"method": "lora"`): each stage trains a fresh rank-64 adapter (OCT's settings, plus its KL term for DPO), saves it to `<stage>/adapter/`, and merges it into the weights; the merged checkpoint feeds the next stage. The DPO reference is the stage's input checkpoint. No length limit (`"max_length": null`).
4. **Publishing** (`recursive_oct/publish.py`): each adapter goes to the repo as `round_NNN/dpo` or `round_NNN/sft`, with its `training_complete.json` (and the round's constitution for SFT). A failed upload is recorded in `publish_failed.json` and retried after the next SFT stage. Preference data is never uploaded (it contains LIMA prompts).
5. **Disk**: after each SFT stage, the round's DPO checkpoint and the previous round's final checkpoint lose their weight shards (`weights_deleted.json`); `agents/scripts/rebuild_checkpoint.py` rebuilds any stage from the base and the adapters, bit for bit on a GPU.
6. **Evaluation** is deferred (`"evaluation": null`): checkpoints are rebuilt and evaluated after training.

The stage 07 broad-draft chains (`runs/selfhost/selfhost-v3-chains-reflect/qwen38_27b_vllm__reflect__broad_draft__r1`, `__r2`) are the editing-only controls: same model, review, prompts, and server settings, no training.

## Pod

1. Create an H200 pod from the official PyTorch template (`runpod-torch-v280`, `--min-cuda-version 13.0`, `--container-disk-in-gb 500`, `--ports '22/tcp'`, `--wait`). The vLLM image hung in `awaiting_container` in stage 08.
2. Push the project (`agents/scripts/sync.py push`, which skips `runs/`), then copy what the bootstrap and run need from `runs/` and `data/`: `runs/training-environment.freeze.txt`, `runs/inference-environment.freeze.txt`, `runs/build_support/`, and `data/raw/lima/prompts.jsonl`.
3. Copy the HF token to `/workspace/.hf_token` (mode 600) without printing it; the run reads `HF_TOKEN` from the environment.
4. `bash agents/scripts/setup_oct_loop_pod.sh`: training environment from the archived freeze (with causal-conv1d built for SM90), `peft==0.21.0`, a vLLM 0.30.0 environment at `/workspace/venv-vllm`, and the base model at the pinned revision.
5. Write a spending ledger for the approved ceiling (`recursive_oct/budget.py` format) and launch:

   ```
   export HF_HOME=/workspace/huggingface HF_TOKEN=$(cat /workspace/.hf_token)
   nohup /workspace/venv/bin/python agents/scripts/run_experiment.py --config configs/oct-loop/<config>.json \
       --run runs/oct-loop/<label> --ledger runs/oct-loop/spending.json > runs/oct-loop/<label>.log 2>&1 &
   ```

   Rerunning the same command with `--resume` continues from the last finished phase.

## At the pause after round 1

- Sync the code before anything else: round 1 ran with the code as of its launch (the pod's copy was not updated mid-round). Later rounds use the recipe changes made during round 1: one 4,096-token teacher limit (no thinking cap), student answers 4,096, no pair limit, reflections 4,096, conversation turns 2,048, batches of 2,048 prompts.
- Round 1's data used the old repetition filter (an 8-word phrase 3 times). It dropped 1,413 of 10,000 reflections, only 114 of them loops, and about half of prompts 02 (diary) and 07 (future AI); and 143 DPO pairs. The code now uses 16 words 5 times. Not refiltered for round 1: SFT was 60% done when this was found (user left the restart open; the no-action path was taken).
- Self-conversations from round 2 (user, 2026-09-28): no canned prelude for copy B (`interaction_speaker_b_prelude: false`) and drop conversations whose trained last turn is a fragment (`drop_fragment_last_turn: true`); both set in `configs/oct/recipe-*.json`. The run's saved `config.json` still has round 1's settings and must be updated at the pause like the other recipe changes. The eval's self-talk task follows the run config's prelude setting.
- Then compare the teacher's two thinking reminders (`agents/scripts/compare_teacher_reminders.py`, 100 prompts, a few minutes): with the constitution repeated after the reminder, the teacher closed its thinking at once in 94% of round 1's answers; `"teacher_reminder": "short"` drops the repeat. The user chooses for rounds 2-5.
- The run's saved `config.json` must then be updated to the new settings (documented protocol change between rounds), and the protocol snapshot refreshed for the changed recipe file.
